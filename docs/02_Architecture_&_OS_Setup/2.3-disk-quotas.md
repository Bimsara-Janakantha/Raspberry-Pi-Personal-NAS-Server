# 2.3 — Enforcing Hardware-Level Disk Quotas

## Overview

Storage quotas limit how much disk space each user can consume. This NAS enforces quotas at the **Linux kernel / ext4 filesystem level** — not just inside Nextcloud.

**Why not just use Nextcloud's built-in quota setting?**

Nextcloud's quota only applies when files are uploaded through its web interface or app. If a user maps the NAS as a **network drive** (e.g., a `Z:` drive on Windows via Samba), they can write files directly to the filesystem and completely bypass Nextcloud's quota counter. Kernel-level quotas have no such loophole — the filesystem itself refuses writes once the limit is hit, regardless of how the user is connected.

**Quota Allocations for this build:**

| User  | Quota |
| ----- | ----- |
| user1 | x TB  |
| user2 | y TB  |

---

## Prerequisites

- The storage array must be mounted with `usrquota,grpquota` flags in `/etc/fstab`  
  _(Covered in [2.1 — Storage Architecture](./2.1-storage-architecture.md))_
- User accounts must exist  
  _(Covered in [2.2 — User Accounts](./2.2-user-accounts.md))_

---

## Step 1 — Install Quota Tools

```bash
sudo apt install quota quotatool
```

- `quota` — the main Linux quota management package
- `quotatool` — provides additional utilities for scripting and inspection

---

## Step 2 — Initialise the Quota Database

This scans the filesystem and creates the quota accounting files. Run this once when setting up quotas for the first time.

```bash
sudo quotacheck -cum /mnt/NAS_Storage
```

> 📝 **Flag reference:**
> | Flag | Meaning |
> |------|---------|
> | `-c` | Create new quota files |
> | `-u` | Check user quotas |
> | `-m` | Force check even if filesystem appears mounted |

---

## Step 3 — Enable the Quota System

Turn on quota enforcement on the storage mount:

```bash
sudo quotaon -v /mnt/NAS_Storage
```

The `-v` (verbose) flag prints confirmation that quotas were activated. You should see output similar to:

```
/dev/sda1 [/mnt/NAS_Storage]: user quotas turned on
```

---

## Step 4 — Set Per-User Limits

Open the quota editor for each user. The editor opens a table where you set the `soft` and `hard` block limits.

```bash
sudo edquota -u user1
```

This opens a text editor showing something like:

```
Disk quotas for user user1 (uid 1001):
  Filesystem    blocks   soft   hard   inodes   soft   hard
  /dev/sda1         0      0      0        0      0      0
```

Edit **only the `hard` value under `blocks`**. Leave `soft` and inode limits at `0` (unlimited) unless you specifically need them.

### Quota Size Reference

Linux quotas are measured in **Kilobytes (KB)**.

| Target Size | Kilobytes | Who   |
| ----------- | --------- | ----- |
| x TB        | `X`       | user1 |
| y TB        | `Y`       | user2 |

**Formula:** `TB × 1024 × 1024 × 1024 = KB value`

**After editing, the user1 entry should look like:**

```
Disk quotas for user user1 (uid 1001):
  Filesystem      blocks    soft        hard   inodes   soft   hard
  /dev/sda1            0       0  5368709120        0      0      0
```

Save and exit (`Ctrl+X` → `Y` → `Enter` if using nano, or `:wq` in vi).

Repeat for user2:

```bash
sudo edquota -u user2
```

Set `hard` to `1610612736` for user2.

---

## Step 5 — Verify Quotas Are Applied

Check that the quotas were saved correctly:

```bash
sudo quota -vs user1
sudo quota -vs user2
```

You should see each user's hard limit displayed in human-readable units.

To see all users at once:

```bash
sudo repquota -as /mnt/NAS_Storage
```

---

## How Quotas Behave

| Scenario                           | Result                                                     |
| ---------------------------------- | ---------------------------------------------------------- |
| User uploads via Nextcloud web     | Quota counted and enforced                                 |
| User writes via mapped Samba drive | Quota counted and enforced                                 |
| User reaches hard limit            | Write is rejected at OS level — no more files can be saved |
| Soft limit (if set)                | User gets a grace period warning before writes are blocked |

> 💡 **Tip:** In this setup, only a `hard` limit is set. The `soft` limit is left at 0 (disabled). This means users hit a hard wall at their limit with no grace period. If you want to warn users before they hit the limit, set a `soft` limit slightly below `hard` and configure a grace period with `sudo edquota -t`.
