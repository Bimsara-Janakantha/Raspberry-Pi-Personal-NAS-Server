# 2.2 — Creating User Accounts

## Overview

Every person who uses this NAS gets their own **Linux OS-level user account**. This is a deliberate architectural choice — it is not just a Nextcloud setting.

**Why create OS-level users instead of just Nextcloud users?**

| If users only existed in Nextcloud... | With OS-level users... |
|--------------------------------------|------------------------|
| File ownership is all under one generic `www-data` account | Each person genuinely owns their files at the OS level |
| Storage quotas can be bypassed by mapping a network drive | Quotas are enforced by the kernel — impossible to bypass |
| A Nextcloud bug or reset could lose access control | User access is independent of any application layer |
| Auditing file access is difficult | Standard Linux audit tools work natively |

---

## Step 1 — Create the User Accounts

```bash
sudo adduser user1
```

The system will prompt for a password and optional profile information. Set a strong password — this account controls access to potentially terabytes of personal files.

```bash
sudo adduser user2
```

Repeat for each user who will have their own storage vault on the NAS.

> 💡 **Naming convention:** Use lowercase, no spaces. Keep usernames short and consistent — they appear in file paths, Samba shares, and log files.

---

## Step 2 — Create Personal Storage Vaults

Each user gets a dedicated directory on the HDD storage array. This is their private vault — no other user can read or write to it by default.

```bash
sudo mkdir -p /mnt/NAS_Storage/user1
sudo mkdir -p /mnt/NAS_Storage/user2
```

> 📝 The `-p` flag creates any missing parent directories and does not error if the directory already exists.

---

## Step 3 — Assign Ownership

This is the critical step. Without correct ownership, the quota system cannot track usage per user, and file permissions will be wrong.

```bash
sudo chown -R user1:user1 /mnt/NAS_Storage/user1
sudo chown -R user2:user2 /mnt/NAS_Storage/user2
```

> 📝 **What does `chown -R user:group path` mean?**
> - `chown` = change owner
> - `-R` = recursive (apply to all files and subdirectories inside)
> - `user1:user1` = set both the user owner and group owner to `user1`
> - `/mnt/NAS_Storage/user1` = the target directory

---

## Step 4 — Verify Ownership

Confirm the permissions look correct:

```bash
ls -la /mnt/NAS_Storage/
```

Expected output:

```
drwxr-xr-x  4 root     root      4096 Jan  1 00:00 .
drwxr-xr-x  3 root     root      4096 Jan  1 00:00 ..
drwxr-xr-x  2 user1    user1     4096 Jan  1 00:00 user1
drwxr-xr-x  2 user2    user2     4096 Jan  1 00:00 user2
```

The third and fourth columns show the owner and group. Each user should own their own directory.

---

## Adding More Users Later

To add a new user to the NAS in the future, repeat all four steps:

```bash
sudo adduser newusername
sudo mkdir -p /mnt/NAS_Storage/newusername
sudo chown -R newusername:newusername /mnt/NAS_Storage/newusername
# Then apply their quota — see 2.3-disk-quotas.md
```
