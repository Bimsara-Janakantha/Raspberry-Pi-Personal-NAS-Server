# 2.4 — Samba Local Network Access

## Overview

Samba exposes each user's storage vault as a **Windows network share (SMB)** on the local network. When connected to the home network, users can map this share as a drive letter (e.g., `Z:`) in Windows File Explorer and drag-and-drop files at full LAN speed — no internet, no Nextcloud overhead.

**When to use Samba vs Nextcloud:**

| Use Case | Recommended Method |
|----------|--------------------|
| Migrating a large archive of old files (400GB+) | **Samba** — direct LAN, full speed |
| Day-to-day file sync across devices | **Nextcloud** — handles versioning, mobile apps, remote access |
| Accessing files remotely (outside home network) | **Nextcloud + Cloudflare Tunnel** |
| One-off large file copy on local network | **Samba** |

> ⚠️ **Security note:** The Samba shares in this setup are accessible to anyone on the local network who knows the credentials. They are **not exposed to the internet**. Do not port-forward Samba ports (445, 139) through your router.

---

## Step 1 — Install Samba

```bash
sudo apt install samba
```

---

## Step 2 — Create Samba Passwords

Samba maintains its own password database, separate from Linux login passwords. Each user needs a Samba password to authenticate when connecting from Windows.

```bash
sudo smbpasswd -a user1
sudo smbpasswd -a user2
```

You will be prompted to enter and confirm a password for each user. These are the credentials users will type in Windows when connecting to the share.

> 💡 **Tip:** You can set the Samba password to the same value as the Linux login password for simplicity, or use a different one for additional separation.

---

## Step 3 — Configure the Network Shares

Open the Samba configuration file:

```bash
sudo nano /etc/samba/smb.conf
```

Scroll to the **very bottom** of the file and add the following blocks:

```ini
[User1_Vault]
path = /mnt/NAS_Storage/user1
writeable = yes
valid users = user1

[User2_Vault]
path = /mnt/NAS_Storage/user2
writeable = yes
valid users = user2
```

> 📝 **Configuration explained:**
> | Option | Meaning |
> |--------|---------|
> | `[User1_Vault]` | The share name — this is what appears in Windows File Explorer |
> | `path` | The physical directory on the NAS this share points to |
> | `writeable = yes` | Users can create, edit, and delete files (not read-only) |
> | `valid users` | Only this Linux user can authenticate to this share |

Save and exit: `Ctrl+X` → `Y` → `Enter`

---

## Step 4 — Restart Samba

Apply the configuration changes:

```bash
sudo systemctl restart smbd
```

Verify Samba is running:

```bash
sudo systemctl status smbd
```

You should see `active (running)` in green.

---

## Step 5 — Connect from Windows

1. Open **File Explorer**
2. In the address bar, type the NAS address in this format:
   ```
   \\<NAS-IP-ADDRESS>
   ```
   For example: `\\192.168.1.100`
3. Windows will prompt for credentials — enter the Samba username and password set in Step 2
4. You will see `User1_Vault` and `User2_Vault` listed as available shares
5. Right-click a share → **Map network drive** → assign a drive letter (e.g., `Z:`)

> 💡 **Finding your NAS IP:** Run `hostname -I` on the Raspberry Pi to see its current IP address. For a reliable connection, assign the Pi a static IP on your router (by MAC address reservation).

---

## Verification Checklist

- [ ] `samba` installed without errors
- [ ] Samba passwords set for both users via `smbpasswd -a`
- [ ] Share blocks added to bottom of `/etc/samba/smb.conf`
- [ ] `sudo systemctl restart smbd` completed without errors
- [ ] `sudo systemctl status smbd` shows `active (running)`
- [ ] Windows can browse to `\\<NAS-IP>` and see the shares
- [ ] Each user can authenticate and read/write files in their vault
