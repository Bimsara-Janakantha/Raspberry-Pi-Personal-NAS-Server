# 2.5 — Bulk File Transfer & Nextcloud Resync

## Overview

When migrating a large archive of existing files (hundreds of gigabytes), uploading through the Nextcloud web interface is impractical. Instead, files are copied **directly to the filesystem via Samba**, then Nextcloud is told to scan and index them.

This is a three-phase process:

```
Phase 1: Open permissions → Phase 2: Copy files via Samba → Phase 3: Scan + restore security
```

> ⚠️ **Heads up:** Phase 1 temporarily opens folder permissions wide. Do not leave the system in this state. Complete all three phases in one session.

---

## Why This Process Is Necessary

Nextcloud manages files through its own PHP application layer. When files are placed directly on the filesystem (bypassing the web interface), Nextcloud has no record of them in its database — they are invisible in the UI.

The `files:scan` command in Phase 3 forces Nextcloud to crawl the raw filesystem and register every file it finds, making them visible as if they had been uploaded normally.

Additionally, Nextcloud's file ownership model uses a system user called `www-data`. When you write files via Samba (as your personal Linux user), there will be an ownership conflict — Nextcloud cannot manage files it does not own. Phases 1 and 3 handle this correctly.

---

## Phase 1 — Temporarily Open Permissions

Before copying, grant full access to the vault so there are no permission errors during the file transfer:

```bash
sudo chmod -R 777 /mnt/NAS_Storage/user1
```

> 📝 `chmod 777` grants read, write, and execute to everyone (owner, group, others). This is intentionally temporary — it is closed back down in Phase 3.

---

## Phase 2 — Copy Files via Windows

With permissions open, connect to the Samba share from Windows and copy your files:

1. Open **File Explorer** and navigate to the mapped `Z:` drive (your Samba share)  
   *(If not yet mapped, see [2.4 — Samba Local Access](./2.4-samba-local-access.md) Step 5)*
2. Drag and drop — or copy/paste — all files you want to migrate into the share
3. Wait for the transfer to complete fully before proceeding to Phase 3

> 💡 **Transfer speed tip:** On a gigabit local network, expect 50–100 MB/s sustained. A 400GB archive takes roughly 70–130 minutes. Keep the Pi and your PC both plugged into a wired ethernet switch for maximum speed.

---

## Phase 3 — Scan Files into Nextcloud & Restore Security

Once all files are copied, run these commands **in order**:

### 3a — Force Nextcloud to Index the New Files

Nextcloud is running inside Docker. This command executes the file scanner inside the Nextcloud container:

```bash
sudo docker exec --user www-data nextcloud php occ files:scan --all
```

This crawls every file on the storage array and adds any unregistered files to Nextcloud's database. Progress will be printed to the terminal — it may take several minutes for a large archive.

> ⚠️ **If you get a permission error** running the command above, try this alternative (uses numeric UID `33` for `www-data`):
> ```bash
> sudo docker exec -u 33 nextcloud php occ files:scan --all
> ```

### 3b — Restore Correct Ownership

After the scan, restore proper file ownership so that:
- The Linux user (`user1`) retains personal ownership for quota tracking
- Nextcloud's `www-data` system user has group-level access to manage the files

```bash
sudo chown -R user1:www-data /mnt/NAS_Storage/user1
sudo chmod -R 775 /mnt/NAS_Storage/user1
```

> 📝 **Permission breakdown:**
> | Command | What it does |
> |---------|-------------|
> | `chown -R user1:www-data` | Owner = user1 (quota tracks against them), Group = www-data (Nextcloud can manage files) |
> | `chmod -R 775` | Owner: read/write/execute · Group: read/write/execute · Others: read/execute only |

---

## Repeating for Other Users

Run the same three phases for each additional user, substituting their username:

```bash
# Phase 1
sudo chmod -R 777 /mnt/NAS_Storage/user2

# Phase 2 — copy files via Windows/Samba (manual step)

# Phase 3
sudo docker exec --user www-data nextcloud php occ files:scan --all
sudo chown -R user2:www-data /mnt/NAS_Storage/user2
sudo chmod -R 775 /mnt/NAS_Storage/user2
```

---

## Verification Checklist

- [ ] Phase 1: `chmod 777` applied — no errors
- [ ] Phase 2: All files copied via Windows File Explorer — transfer complete
- [ ] Phase 3a: `files:scan --all` ran successfully — file counts printed
- [ ] Phase 3b: `chown` and `chmod` restored — no errors
- [ ] Log into Nextcloud web UI — migrated files are now visible in each user's account
- [ ] Check that user storage usage in Nextcloud reflects the transferred files
