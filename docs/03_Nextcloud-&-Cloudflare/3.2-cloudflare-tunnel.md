# 3.2 — Cloudflare Zero Trust Tunnel

## Overview

To access your NAS from outside your home — from work, on your phone on mobile data, or while travelling — you need a way to reach it over the internet. The traditional method is **port forwarding**, where you open a hole in your home router to let external traffic through. This works, but it has serious downsides:

| Port Forwarding | Cloudflare Zero Trust Tunnel |
|-----------------|------------------------------|
| Exposes your home IP address | Your home IP is never revealed |
| Opens an attack surface on your router | No ports opened on your router at all |
| Requires a static IP or dynamic DNS service | Works with any internet connection |
| Traffic is only as secure as your setup | Traffic is encrypted end-to-end by Cloudflare |
| Free | Also free (Cloudflare's free tier covers this) |

**How the tunnel works — in plain English:**

> Instead of the internet knocking on your door, your Pi reaches *out* to Cloudflare and holds a persistent secure connection open. When someone visits your domain, Cloudflare passes the request through that existing outbound connection — your router never sees an incoming connection at all.

---

## Prerequisites

Before starting this section you need:
- A **domain name** (e.g., `justinnas.dev`) — purchase from any registrar (Namecheap, Cloudflare, Google Domains, etc.)
- A **Cloudflare account** (free) at [cloudflare.com](https://cloudflare.com)
- Your domain's **nameservers pointed to Cloudflare** — done in your domain registrar's settings

> 💡 **Pointing your domain to Cloudflare:** In your domain registrar's DNS settings, replace the default nameservers with the two Cloudflare nameservers shown in your Cloudflare dashboard (they look like `ada.ns.cloudflare.com`). This hands DNS control to Cloudflare. It can take up to 24 hours to propagate, but usually completes within an hour.

---

## Step 1 — Create a Zero Trust Tunnel in Cloudflare

1. Log in at [cloudflare.com](https://cloudflare.com)
2. From the left sidebar, click **Zero Trust**
3. Navigate to **Networks** → **Tunnels**
4. Click **Create a tunnel**
5. Select **Cloudflared** as the connector type
6. Give the tunnel a name — e.g., `raspi-nas`
7. Click **Save tunnel**

Cloudflare will now show you an **installation command** that looks like:

```bash
sudo cloudflared service install eyJhIjoiM....(long token here)
```

**Copy this entire command** — you will run it on the Pi in Step 3.

---

## Step 2 — Install cloudflared on the Raspberry Pi

`cloudflared` is the software that creates and maintains the tunnel connection from your Pi to Cloudflare.

Install it on the Pi:

```bash
# Download the ARM64 package for Raspberry Pi 5
wget https://github.com/cloudflare/cloudflared/releases/latest/download/cloudflared-linux-arm64.deb

# Install the package
sudo dpkg -i cloudflared-linux-arm64.deb
```

---

## Step 3 — Connect the Pi to Your Tunnel

Now run the installation command you copied from the Cloudflare dashboard in Step 1:

```bash
sudo cloudflared service install eyJhIjoiM....(your full token here)
```

This registers your Pi with Cloudflare and installs `cloudflared` as a background service that starts automatically on every reboot.

Verify the service is running:

```bash
sudo systemctl status cloudflared
```

You should see `active (running)`. Back in the Cloudflare dashboard, the tunnel status should change to a green **Healthy** indicator.

---

## Step 4 — Configure the Public Hostname

This step tells Cloudflare: *"When someone visits this domain, forward them to this local address."*

In the Cloudflare Zero Trust dashboard:

1. Go to **Networks** → **Tunnels** → click your tunnel → **Edit**
2. Click the **Public Hostname** tab
3. Click **Add a public hostname**
4. Fill in the form:

| Field | Value |
|-------|-------|
| **Subdomain** | `cloud` |
| **Domain** | `justinnas.dev` *(your domain)* |
| **Type** | `HTTP` |
| **URL** | `192.168.2.245:7580` *(your Pi's local IP and Nextcloud port)* |

> 📝 **Why HTTP and not HTTPS here?**  
> The URL field describes the connection *between Cloudflare's tunnel and your Pi* — which is a private local network connection. HTTPS is applied *externally* by Cloudflare automatically. Using HTTP internally is correct and avoids certificate complications.

5. Click **Save hostname**

Your Nextcloud is now reachable at `https://cloud.justinnas.dev` — HTTPS is automatically provided by Cloudflare's edge.

---

## Step 5 — Force the Correct Host Header

This is a subtle but important configuration step that prevents a confusing problem.

**The problem:** When Cloudflare forwards a request through the tunnel to your Pi, Nextcloud receives it and thinks: *"Who am I? What's my address?"* Because the request arrives via a local IP (`192.168.2.245`) rather than the public domain, Nextcloud can generate broken internal links, wrong redirect URLs, or refuse to serve pages correctly.

**The fix:** Tell Cloudflare to always send the public domain name as part of every request, so Nextcloud knows its true public identity.

In the Cloudflare dashboard, while editing your public hostname:

1. Scroll down to **Additional application settings**
2. Expand **HTTP Settings**
3. Find the **HTTP Host Header** field
4. Enter your full domain:
   ```
   cloud.justinnas.dev
   ```
5. Save

Now every request that arrives at Nextcloud includes the header `Host: cloud.justinnas.dev` — Nextcloud always knows who it is.

---

## Step 6 — Verify Remote Access

Test the tunnel from a device **not connected to your home Wi-Fi** (use mobile data or a VPN):

1. Open a browser
2. Navigate to `https://cloud.justinnas.dev`
3. The Nextcloud login page should appear with a valid padlock (HTTPS)

If the page does not load, check:
- `sudo systemctl status cloudflared` on the Pi — is the service running?
- Cloudflare dashboard → Tunnels — does it show **Healthy**?
- Is Nextcloud itself running? Test `http://192.168.2.245:7580` from inside your home network
