# 3.1 — Nextcloud Docker Stack & Storage Mapping

## Overview

Nextcloud runs as a set of Docker containers managed by **CasaOS** — a friendly dashboard that runs on the Raspberry Pi and lets you install and manage self-hosted apps without writing Docker commands by hand.

Rather than a single container, this deployment uses a **multi-container stack** where each component has its own dedicated container. This is the professional way to run Nextcloud — each piece does one job and does it well.

---

## Understanding the Container Stack

Before touching anything, it helps to understand what each container does:

| Container | What it does | Why it's separate |
|-----------|-------------|-------------------|
| **Nextcloud App** | The web server — serves the UI, handles uploads, responds to apps | The face of the system, listens on port `7580` |
| **PostgreSQL** | The database — stores file metadata, user accounts, activity logs, share links | Databases need their own isolated environment for stability |
| **Redis** | In-memory cache — remembers recent queries so the UI loads faster | Keeps cache data separate from persistent database data |
| **Cron** | Background worker — generates thumbnails, empties trash, runs maintenance | Must run even when no user is logged in |

> 💡 **What is Docker?** Docker is a system that runs applications in isolated "containers" — like separate mini-computers inside your Pi. Each container has exactly the software it needs and nothing else. This keeps things clean, portable, and easy to update.

---

## Step 1 — Install CasaOS

CasaOS is the management dashboard that makes running Docker containers approachable. Install it with a single command on the Raspberry Pi:

```bash
curl -fsSL https://get.casaos.io | sudo bash
```

Once installed, CasaOS is accessible from your browser at:
```
http://<YOUR-PI-IP-ADDRESS>
```

> 💡 **Finding your Pi's IP:** Run `hostname -I` on the Pi. The first address shown is your local IP (e.g., `192.168.2.245`).

Complete the CasaOS first-run setup — create an admin username and password when prompted.

---

## Step 2 — Install the Nextcloud Stack

This build uses a pre-packaged Nextcloud image from BigBearTechWorld that bundles PostgreSQL, Redis, and Cron together — saving you from wiring them up manually.

**Image used:**
```
bigbeartechworld/big-bear-nextcloud-with-smbclient:33.0.0
```

**In CasaOS:**
1. Open the **App Store** from the CasaOS dashboard
2. Search for **Nextcloud**
3. Find the **Big Bear Nextcloud** entry (the one that includes smbclient)
4. Click **Install**
5. Before confirming, proceed to Step 3 to configure the volume mappings first

---

## Step 3 — Map the Storage Array to the Containers

This is the most important configuration step. By default, Docker containers are completely isolated — they cannot see your hard drives. You must explicitly tell Docker to connect the 3×4TB storage array into the containers.

Without this mapping, Nextcloud will try to store all user files inside the container itself — which lives on your SD card or the 1TB drive. That is not what you want.

### Mapping for the Main App Container

Inside the CasaOS Nextcloud installation settings, find the **Volumes** section and add:

| Host Path (on your Pi) | Container Path (inside Docker) |
|------------------------|-------------------------------|
| `/mnt/NAS_Storage` | `/NAS_Storage` |

**What this means in plain English:**
> "Whenever the Nextcloud container looks inside `/NAS_Storage`, it is actually reading and writing to `/mnt/NAS_Storage` on the real Pi filesystem — which is your 3×4TB physical drive array."

### The Cron Container — A Critical Extra Step

> ⚠️ **Do not skip this.** This is one of the most common causes of mysterious errors in Nextcloud deployments.

The `cron` background container runs completely independently of the main app — it has its own filesystem, its own environment. If you only mapped the storage volume to the main app, the cron container has **no idea the drives exist**.

**Symptoms if you miss this:**
- Background jobs silently fail
- Thumbnails never generate
- Log files fill up with `StorageNotAvailableException` errors
- Trash cleanup never runs

**The fix — add the same volume mapping to the Cron container:**

1. In CasaOS → open Nextcloud settings
2. Navigate to the **`cron`** tab (not the main app tab)
3. Find the **Volumes** section
4. Add the exact same mapping:

| Host Path | Container Path |
|-----------|---------------|
| `/mnt/NAS_Storage` | `/NAS_Storage` |

Both the main app and the cron container must see the same path.

---

## Step 4 — Configure the Storage Location in Nextcloud

After the containers are running and the volume is mapped, tell Nextcloud to use the mapped path as the data directory.

During the **Nextcloud first-run setup wizard** (accessed in your browser at `http://<PI-IP>:7580`):

1. Set an admin username and password
2. Under **Storage & database**, change the **Data folder** path from the default to:
   ```
   /NAS_Storage
   ```
   *(This is the container-side path — it maps to your physical `/mnt/NAS_Storage` drive)*
3. Under **Database**, select **PostgreSQL** and fill in the credentials that were set during the CasaOS installation

---

## Step 5 — Verify the Stack is Running

Back in CasaOS, all four containers should show a green **Running** status:

```
✅ nextcloud      (running)
✅ nextcloud-db   (running)
✅ nextcloud-redis (running)
✅ nextcloud-cron  (running)
```

If any container shows red or is restarting, click it to view the logs and identify the error.

You can also check from the Pi terminal:

```bash
sudo docker ps
```

This lists all running containers with their status and the ports they are listening on.

---

## Understanding the Port

The Nextcloud web interface listens on **port 7580** locally. This means:

- From inside your home network: `http://192.168.2.245:7580`
- From the internet: `https://cloud.justinnas.dev` *(via the Cloudflare tunnel set up in [3.2](./3.2-cloudflare-tunnel.md))*

Port 7580 is deliberately not 80 or 443 (the standard web ports) to avoid conflicts with CasaOS's own web server.
